# Бэклог продукта

## Цель и исходные данные
Бэклог описывает истории электронного сервиса библиотеки кафедры. Полный учебный бэклог содержит 17 историй; в MVP входят 10. Story Points — предварительные командные оценки, которые необходимо подтвердить на реальной сессии Planning Poker.

Формат каждой истории: «Как …, я хочу …, чтобы …». Для каждой истории приведены минимум два критерия приёмки в формате **Дано / Когда / Тогда**. Зависимости перечислены явно.

## US01 — Просмотр каталога книг

**Как студент, я хочу просматривать каталог книг, чтобы быстро находить литературу, доступную на кафедре.**

- **Оценка:** 3 SP
- **Зависимости:** нет
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** В базе есть не менее двух книг. **Когда:** пользователь запрашивает каталог. **Тогда:** API возвращает список книг с идентификатором, названием, автором и количеством доступных экземпляров.
  2. **Дано:** В базе нет книг. **Когда:** пользователь запрашивает каталог. **Тогда:** API возвращает пустой список и корректный ответ без ошибки сервера.
- **Проверка INVEST:** Самостоятельная ценность; небольшой объём; результат проверяется ответом API.

## US02 — Поиск по названию и автору

**Как студент, я хочу искать книгу по названию или автору, чтобы находить нужную книгу без просмотра всего каталога.**

- **Оценка:** 3 SP
- **Зависимости:** US01
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** В каталоге есть книга с совпадением в названии или авторе. **Когда:** пользователь отправляет поисковый запрос. **Тогда:** возвращаются книги, у которых название или автор содержит запрос без учёта регистра.
  2. **Дано:** Ни одна книга не соответствует запросу. **Когда:** пользователь выполняет поиск. **Тогда:** API возвращает пустой список, а не ошибку сервера.
- **Проверка INVEST:** Зависит от каталога, но реализуется отдельной функцией; запрос и результат тестируемы.

## US03 — Карточка книги и доступность

**Как студент, я хочу открывать подробную карточку книги, чтобы понимать, кто автор книги и есть ли свободные экземпляры.**

- **Оценка:** 2 SP
- **Зависимости:** US01
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Книга с указанным идентификатором существует. **Когда:** пользователь запрашивает карточку. **Тогда:** ответ содержит название, автора, год, категорию и количество экземпляров.
  2. **Дано:** Книги с указанным идентификатором нет. **Когда:** пользователь запрашивает карточку. **Тогда:** API возвращает 404 и не раскрывает внутреннюю ошибку.
- **Проверка INVEST:** Небольшая, полезная и проверяемая история; зависимость от каталога указана.

## US04 — Добавление книги в каталог

**Как библиотекарь, я хочу добавлять книгу с количеством экземпляров, чтобы поддерживать каталог в актуальном состоянии.**

- **Оценка:** 3 SP
- **Зависимости:** US13
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Библиотекарь авторизован и передал название, автора и положительное количество экземпляров. **Когда:** библиотекарь отправляет запрос на создание книги. **Тогда:** создаётся запись со статусом 201, доступное количество равно общему количеству.
  2. **Дано:** Не заполнено обязательное поле или количество экземпляров меньше единицы. **Когда:** библиотекарь отправляет запрос на создание книги. **Тогда:** API возвращает 400 с понятным описанием ошибки, запись не создаётся.
- **Проверка INVEST:** Ограничена созданием одной записи; поля и ошибки определены; требует авторизации.

## US05 — Редактирование данных книги

**Как библиотекарь, я хочу изменять метаданные существующей книги, чтобы исправлять опечатки и обновлять сведения.**

- **Оценка:** 3 SP
- **Зависимости:** US04, US13
- **Состав релиза:** после MVP
- **Критерии приёмки:**
  1. **Дано:** Книга существует и библиотекарь авторизован. **Когда:** библиотекарь отправляет корректные новые метаданные. **Тогда:** изменения сохраняются и видны при повторном запросе карточки.
  2. **Дано:** Книги с указанным идентификатором нет. **Когда:** библиотекарь отправляет запрос на изменение. **Тогда:** API возвращает 404, другие записи не меняются.
- **Проверка INVEST:** Отдельная небольшая операция; может быть выпущена после создания записи; тестируется повторным чтением.

## US06 — Регистрация выдачи книги

**Как библиотекарь, я хочу фиксировать выдачу книги читателю, чтобы вести учёт того, у кого находится экземпляр.**

- **Оценка:** 5 SP
- **Зависимости:** US04, US08, US13
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Книга существует, есть доступный экземпляр, читатель указан и библиотекарь авторизован. **Когда:** библиотекарь регистрирует выдачу. **Тогда:** создаётся активная запись выдачи с датой выдачи и сроком возврата.
  2. **Дано:** Не указаны обязательные данные или книга не существует. **Когда:** библиотекарь регистрирует выдачу. **Тогда:** API возвращает понятную ошибку, запись выдачи не создаётся.
- **Проверка INVEST:** Оценка 5 SP — верхняя граница размера истории; бизнес-правила выделены в US08.

## US07 — Регистрация возврата книги

**Как библиотекарь, я хочу отмечать возврат ранее выданной книги, чтобы актуализировать доступность экземпляров.**

- **Оценка:** 3 SP
- **Зависимости:** US06
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Выдача существует и ещё активна. **Когда:** библиотекарь регистрирует возврат. **Тогда:** выдача получает статус «возвращена», дата возврата сохраняется.
  2. **Дано:** Выдача не существует или уже закрыта. **Когда:** библиотекарь повторно регистрирует возврат. **Тогда:** API возвращает 404 или 409, повторное увеличение доступного количества не происходит.
- **Проверка INVEST:** Небольшая отдельная операция; зависимость от регистрации выдачи явная.

## US08 — Проверка доступности перед выдачей

**Как библиотекарь, я хочу получать отказ, если свободных экземпляров нет, чтобы не допускать отрицательного остатка и двойной выдачи одного экземпляра.**

- **Оценка:** 2 SP
- **Зависимости:** US04
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Количество доступных экземпляров равно нулю. **Когда:** библиотекарь пытается оформить выдачу. **Тогда:** API возвращает 409, новая выдача не создаётся.
  2. **Дано:** Количество доступных экземпляров больше нуля. **Когда:** библиотекарь проверяет доступность книги перед выдачей. **Тогда:** API подтверждает, что выдача возможна; создание записи выдачи и уменьшение остатка выполняются при оформлении выдачи.
- **Проверка INVEST:** Выделена из US06 как отдельное бизнес-правило; проверяется граничными значениями.

## US09 — Просмотр активных выдач

**Как библиотекарь, я хочу просматривать список книг, находящихся у читателей, чтобы контролировать текущие выдачи и сроки возврата.**

- **Оценка:** 3 SP
- **Зависимости:** US06
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** В системе есть активные и завершённые выдачи. **Когда:** библиотекарь запрашивает активные выдачи. **Тогда:** возвращаются только незакрытые выдачи с книгой, читателем и сроком возврата.
  2. **Дано:** Активных выдач нет. **Когда:** библиотекарь запрашивает активные выдачи. **Тогда:** API возвращает пустой список с успешным статусом.
- **Проверка INVEST:** Отдельное представление данных; объём ограничен активными выдачами; тестируется на фикстурах.

## US10 — Фильтр каталога по категории

**Как студент, я хочу фильтровать книги по категории, чтобы быстрее находить литературу нужной тематики.**

- **Оценка:** 3 SP
- **Зависимости:** US01
- **Состав релиза:** после MVP
- **Критерии приёмки:**
  1. **Дано:** В каталоге есть книги нескольких категорий. **Когда:** пользователь выбирает категорию. **Тогда:** возвращаются только книги выбранной категории.
  2. **Дано:** Для категории нет книг. **Когда:** пользователь выбирает категорию. **Тогда:** возвращается пустой список без ошибки сервера.
- **Проверка INVEST:** Самостоятельная функция поиска; реализуется после базового каталога.

## US11 — Очередь ожидания на недоступную книгу

**Как библиотекарь, я хочу добавлять читателя в очередь ожидания, если свободных экземпляров нет, чтобы не терять запросы на популярные книги.**

- **Оценка:** 5 SP
- **Зависимости:** US03, US08, US13
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Книга существует, доступных экземпляров нет, указаны читатель и авторизованный библиотекарь. **Когда:** библиотекарь создаёт заявку ожидания. **Тогда:** заявка сохраняется со статусом «ожидает» и временем создания.
  2. **Дано:** Книга доступна или не указан читатель. **Когда:** библиотекарь пытается создать заявку. **Тогда:** API отклоняет запрос с понятной ошибкой, заявка не создаётся.
- **Проверка INVEST:** История ограничена постановкой в очередь; отмена и уведомления вынесены за пределы MVP.

## US12 — Отмена заявки в очереди ожидания

**Как библиотекарь, я хочу отменять активную заявку ожидания, чтобы поддерживать очередь в актуальном состоянии.**

- **Оценка:** 3 SP
- **Зависимости:** US11
- **Состав релиза:** после MVP
- **Критерии приёмки:**
  1. **Дано:** Заявка существует и ожидает. **Когда:** библиотекарь отменяет заявку. **Тогда:** статус меняется на «отменена», заявка больше не входит в активную очередь.
  2. **Дано:** Заявка не существует или уже обработана. **Когда:** библиотекарь отменяет заявку. **Тогда:** API возвращает 404 или 409, данные не изменяются.
- **Проверка INVEST:** Небольшое продолжение US11; оставлена после MVP, чтобы не раздувать первую поставку.

## US13 — Авторизация библиотекаря

**Как библиотекарь, я хочу входить в систему под своей учётной записью, чтобы защитить операции изменения каталога и выдач.**

- **Оценка:** 5 SP
- **Зависимости:** нет
- **Состав релиза:** MVP
- **Критерии приёмки:**
  1. **Дано:** Переданы корректные учётные данные библиотекаря. **Когда:** пользователь выполняет вход. **Тогда:** API возвращает токен или сессию, разрешающие доступ к защищённым операциям.
  2. **Дано:** Пароль или имя пользователя неверны. **Когда:** пользователь выполняет вход. **Тогда:** API возвращает 401, токен не выдаётся, секреты не попадают в ответ.
- **Проверка INVEST:** Обязательная безопасность для операций записи; ограничена одной ролью и базовым входом.

**Как библиотекарь, я хочу видеть невозвращённые книги с истёкшим сроком, чтобы своевременно связываться с читателями.**

- **Оценка:** 3 SP
- **Зависимости:** US06
- **Состав релиза:** после MVP
- **Критерии приёмки:**
  1. **Дано:** Есть активная выдача со сроком возврата раньше текущей даты. **Когда:** библиотекарь открывает список просроченных выдач. **Тогда:** такая выдача отображается в результате.
  2. **Дано:** Срок возврата сегодня или выдача уже закрыта. **Когда:** библиотекарь открывает список просроченных выдач. **Тогда:** запись не отображается как просроченная.
- **Проверка INVEST:** Отдельный фильтр по существующим выдачам; добавляется после MVP.

- **Зависимости:** US01

  2. **Дано:** Каталог пуст. **Когда:** библиотекарь запрашивает экспорт. **Тогда:** CSV содержит заголовки и корректно скачивается.
- **Проверка INVEST:** Отдельный экспорт существующих данных; можно проверить сравнением количества строк.

  1. **Дано:** В системе есть книги, активные и завершённые выдачи. **Когда:** пользователь запрашивает статистику. **Тогда:** ответ содержит общее число книг, активных выдач и завершённых выдач.
  2. **Дано:** В системе нет выдач. **Когда:** пользователь запрашивает статистику. **Тогда:** счётчики выдач равны нулю, ответ имеет корректный формат.
- **Проверка INVEST:** История ограничена тремя счётчиками; графики и отчёты не входят.

  2. **Дано:** Название пустое или такая категория уже существует. **Когда:** библиотекарь создаёт категорию. **Тогда:** API возвращает 400 или 409, дубликат не создаётся.

## Итоговая проверка INVEST

- **I — Independent:** истории по возможности автономны; необходимые зависимости перечислены и учитываются планировщиком.
- **N — Negotiable:** описывают требуемую пользовательскую ценность, а не предписывают внутреннюю реализацию.
- **V — Valuable:** каждая история даёт проверяемую ценность конкретной роли.
- **E — Estimable:** у каждой истории есть оценка и критерии приёмки.
- **S — Small:** размер каждой истории не превышает 5 SP; статистика и очередь ограничены минимальной функциональностью.
- **T — Testable:** у каждой истории не менее двух критериев приёмки с наблюдаемым результатом.

Все истории прошли первичную проверку INVEST. Перед сдачей команда должна проверить критерии на соответствие выбранной реализации API/Swagger и фактически согласовать оценки.

## Вывод
Бэклог содержит 17 историй с критериями приёмки и явными зависимостями. Все истории ограничены 2–5 SP; обязательные и выбранные истории можно отследить по CSV и трекеру задач.
